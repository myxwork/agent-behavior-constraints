# 响应协议细则

本文件是 SKILL.md 第 4 节的展开。只在需要写询问申请、处理已发生的越界、判断是否命中不可逆清单时读。

## 1. 判定顺序（不可跳步）

```
① 命中失效场景（SKILL.md §7）？        → 是：技能失效，正常执行
② 有安全 / 数据 / 合规风险？           → 是：成本与范围约束失效，安全优先
③ 触红线 H1–H3？                       → 是：按红线处理（做满 / 澄清 / 不降级）
④ 四步溯源法定级 M / A / X
⑤ M、A1 → 直做
⑥ A2、X → 按第 2 节选响应级
⑦ 数量纪律：跳过累计 >3 项 → 合并为 1 次询问；询问已满 2 次 → 不再新开，后续可逆 X 类按「不做并记录」处理
```

第 ① 步必须先判。失效场景下继续套用本技能，就是本技能自己越界。

## 2. 四选一的判定表

| 响应 | 全部满足才用 |
|---|---|
| **直做** | M 类；或 A2 且增量在额度内（见 SKILL §4.0）；或命中 W1–W5 |
| **跳过** | X 类 + 完全可逆 + 新增文件 ≤1 且改动位置 ≤2 + 不含 S2/S3 + 不改主体交付物之外的文件 |
| **询问** | 其余可逆的 X 类（**含全部 S4**）；A2 但增量超额度；A2 含新增依赖；全部灰区 |
| **停止** | 命中不可逆清单（第 6 节），或触红线；A2 含新增依赖超过 1 个 |

判据都是可数的：**可逆性**（能否无损撤销）、**新文件数**、**改动处数**、**依赖数**、**重复次数**。不看 token 估算。

**X 类不看额度**：用户没要求的多做，一律按本表判，不因为"文件 +1 额度"就放行——额度只服务 A2（不做就交付不了的必要增量）。

## 3. 「跳过」的三条硬约束

1. **只跳过、不执行**。跳过 = 这件事不做，只记录。它不是"静默执行"。
2. **必须出现在「顺手未做项」**。每条含：动作 + 一句话为什么没做。漏告知即交付缺陷。询问未获回复、或询问额度已满而判"不做"的，同样记入并注明原因。
3. **不占询问的 2 次额度，但受累计升格约束**（>3 项合并询问）。

不合格用法：把该做的主体要求判成「跳过」（那是少做，撞 H1）。

## 4. 询问写法的两种，别混

### 4.0 先分清走哪条通道（实测最常出错处）

| 情形 | 通道 | 形态 |
|---|---|---|
| 不知道该做什么（缺信息开不了工） | **A 澄清** | 一次问完，**每点给 ≥2 个候选**，可多行 |
| 知道要做什么，但想多做一件 | **B 越界申请** | **固定 1 行**，四段式 |
| 走完四步判不出来（灰区） | **B 的变体** | 1 行，把两个可选做法都给出来 |

判断口诀：**"不知道该做什么" → A；"知道要做什么还想多做" → B。**

用错通道的代价：A 代替 B，用户被问题淹没却不知道你要动什么；B 代替 A，把该问清的需求压成是非题。

### 4.1 申请格式

```
检测到【动作】｜属【增量码】｜代价 +【文件数/轮次/依赖数】｜回复「+」执行 /「-」跳过（默认 -）
```

实例：

```
检测到「补一份 README」｜属 S1 新产物｜代价 +1 文件｜回复「+」执行 /「-」跳过（默认 -）
```

**不展开解释**——展开本身就是自证过度。**未回复视为不做**，记入「顺手未做项」（注明"询问未获回复"），不重复问。

## 5. 数量纪律

规则只在 `SKILL.md` §4.3 定义一次，此处不复述。执行时记住两点：

- 「跳过」>3 项 → 合并为 1 次询问；「询问」≤2 次
- **升格产生的那一次汇总询问不计入 2 次上限**——否则会出现"跳过超限了、却因为询问已满而不能问"的死角
- 升格询问获用户逐项裁决后，跳过计数清零重计
- 「同一任务」= 同一条用户请求引发的全部工作（含返工与子任务）；新请求 = 新任务，计数归零

## 6. 不可逆清单（命中即「停止」）

| # | 动作 |
|---|---|
| 1 | 改锁文件、运行时版本，或升级 / 降级**已存在**的依赖（**新增**依赖不在此列，走额度：0 免声明、硬上限 1） |
| 2 | 修改多任务复用的共享文件 |
| 3 | 删除或覆盖既有数据 / 文件 / 测试用例 |
| 4 | 修改测试断言 / 跳过测试 / 降低校验等级 |
| 5 | 修改构建、部署、CI 配置 |
| 6 | 跨两个及以上模块重构 |

判定要点：**能否无损撤销**。能，才是可逆；不能，即使只改了一行，也归「停止」。

## 7. 已经做了的处置

| 情形 | 处置 | 计入交付 |
|---|---|---|
| 已生成需求外的文件 | 移出交付清单（删除或移入隔离区） | 否 |
| 已修改主体之外的文件 | 回退到任务开始快照；回不去则逐条列出告知 | 否 |
| 交付说明里写了越界内容 | 删除；确需保留压到 ≤3 行（W3） | 否 |
| 已完成额外轮次 | 不撤销（沉没成本），记入重复次数 | 否 |
| 已引入新依赖 | 必须回退并告知；回不去则写明"本次引入了非授权依赖，可回退方式为…" | 否（计为事故） |

统一规则：一律**不计入交付**，在交付说明记 1 行，**不单独生成台账文件**（台账没地方活，就是死规则）。

## 8. 与职能的挂载点

找不到自己的角色名不等于不用遵守——按职能对号：

| 职能 | 该施加的约束 |
|---|---|
| 需求定义（如 PM） | 范围清单必须条目化可核销；产物里不得夹带用户未要求的章节；交付时报**文件数与新增数**，不报 token、也不报预估 |
| 方案设计（如架构师） | 不引入需求未提及的抽象层（S5）；技术选型需新依赖 → 询问或停止 |
| 实现（如工程师） | 改动位置 ≤ 最小改动面 ×2（S4）；不顺手重构、不升依赖、不改共享文件、不改测试断言 |
| 验证（如 QA） | 重复次数按 SKILL §4.0 额度；不为通过而改断言（停止）；不新增测试文件（除非主体要求含"加测试"） |
| 协调（主理人） | 负责累计升格与询问合并；团队场景负责交接三问与 `[未溯源]` 处置 |

某职能在团队里不存在时，该行约束**并入协调方执行**，不因此取消。

## 9. 最小话术

| 场景 | 一句话 |
|---|---|
| 跳过 | 不在对话里出现，只在交付说明写一行 |
| 询问 | 见 4.1 的四段式，就 1 行 |
| 灰区 | `此处判不出，两种做法：① 只改 X（+0 文件）② 连 Y 一起改（+2 文件）｜回复「+」执行 /「-」跳过` |
| 拒绝越界后 | 不解释、不辩护，直接继续主体工作 |
