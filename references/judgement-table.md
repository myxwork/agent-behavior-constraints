# 判定对照表（22 条）

用法：先找最接近的一行直接取结论；表内无对应行时，回 SKILL.md 第 3 节现场判定。**本表不是穷举，是"踩过的坑"清单。**

列含义：**溯源** = 需求原文是否提到；**不做能否交付** = 假设完全不做，主体是否仍成立；**响应级** = 直做 / 跳过 / 询问 / 停止（见 SKILL.md §4）。

## H. 反模式（任何情形一律禁止）

| 行为 | 为什么 |
|---|---|
| 为让测试通过而修改断言、跳过测试、降低校验等级 | 改尺子凑答案，交付不可信 |
| 删除失败的测试用例 | 掩盖问题 |
| 先做后报（做完了才说"我顺便也做了 X"） | 越界已发生且不可逆，知情权被剥夺 |
| 用"提升质量""更专业""行业惯例"论证灰区放行 | 三类理由不构成可核查证据 |
| 自查后直接宣布"无越界" | 自证不等于事实，须逐项溯源、可被抽检 |
| 以"省 token"为由少做主体要求 | 交付失败比浪费更贵 |

## I. 灰区示例（走完四步仍落不了锤 → 询问）

| 情形 | 为什么落灰区 | 处置 |
|---|---|---|
| 用户说"优化一下这个模块" | 最小改动面不可枚举，S4 不能机械套用 | 问清"优化"指性能、可读性还是行为变更，再锁改动面 |
| 用户说"顺便看看有没有别的问题" | "看"是用户说的，列清单属 M；修复所列问题才是新动作 | 列清单**不设条数上限**、只在对话里（M，直做，见 SKILL §3.0）；超过 5 条先问是否全列；动手修复属 X，按四级响应 |
| 一个动作做一半是 M、做全是 X | 边界在动作内部 | M 那一半本身无增量码 → 直做；X 那一半 → 询问 |
