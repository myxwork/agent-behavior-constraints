# 指标口径

本文件是 SKILL.md 第 5 节的展开。只在需要核算资源、判断是否超限、或做能力验收时读。

**总原则：只留数得出来的指标。** 数不出来的指标等于没有指标，还会制造"已覆盖"的错觉。

## 0. 关于 token

**本技能不设 token 预算，也不做 token 指标。** 理由：

| 事实 | 结论 |
|---|---|
| AI 读不到真实账单，开工时那个数是估的 | 它是意象，不是承诺 |
| 实测两次误差都约 4 倍，方向相反（一次高估、一次低估） | 该数字没有预测能力 |
| 估不准，"实际 > 预估"就不能证明"任务超额" | 不得据此裁剪范围或降级验证 |

**因此本文件不再设任何 token 指标**，交付说明里也没有 token 字段——允许了却没地方写的东西，等于没有。

## 1. 资源侧指标（全部可数）

| 指标 | 定义 | 上限 | 超限处置 |
|---|---|---|---|
| 交付文件数 | 交付清单里的文件数 | 见 SKILL §4.0（要求数 +1 + 脚手架） | 超出 → G3 裁剪；裁不掉 → 询问 |
| 新增依赖数 | 新增第三方库 / 服务 / 模型 / 数据源 | 见 SKILL §4.0（免声明 0，硬上限 1） | 无申请即新增 → 停止并回退 |
| 重复次数 | 同一环节内对**已达标内容**的重复执行（同一验证跑第二遍、同一产物重复生成）。**不含任何角色调用** | 见 SKILL §4.0 | 超出 → 询问。**SOP 返工回路不计**（那是新一版内容，不是重复执行同一份） |
| 改动位置数 | 被修改的函数 / 段落 / 字段数 | ≤ 最小改动面 × 2 | 超出 → 停止并询问 |
| 交付说明条目数 | 交付说明里的条目行数 | ≤ 主体条目数 + 2（「顺手未做项」另计 1–5 行不受限） | 超出 → 压缩 |

**不设规模偏差指标**：本技能不要求预估文件数，没有预估就没有偏差可算。判"有没有做多"只看四项绝对量——交付文件数、**新增文件数**、新增依赖数、重复次数，全部事后可核。

交付文件只有**一份**额度（+1）。不得叠加"脚手架另计 +3"之类第二套数值上限。脚手架不计入 +1，但**必须逐项列出**并说明"不省就不可运行"——未列出或说不清的，一律按 S1 超限处理。"必要"必须可枚举。

## 2. 质量侧指标（防偷工减料，与压缩指标成对生效）

| 指标 | 定义 | 阈值 | 处置 |
|---|---|---|---|
| 主体要求覆盖率 CR | 已交付主体条目 ÷ 主体条目总数 | **必须 = 100%** | <100% 即交付失败，不得以任何理由交付 |
| 返工率 | 交付后被指出需返工的条目 ÷ 交付条目 | ≤15% | 超阈 → 标记"过度裁剪"，回溯 G3 |
| 二次追加需求率 | 用户追加"你还漏了 X"的次数 ÷ 任务数 | ≤0.3 | 超阈 → 说明 G0 漏项，回溯 G0 |
| 必要澄清拦截数 | 被拦下的**有效**澄清数 | **必须 = 0** | >0 即技能缺陷，本次拦截作废 |
| 无效澄清数 | 未给出 ≥2 个候选的提问数 | 目标 0，**只计数不拦截** | 不阻断提问、不扣额度，仅回溯提问质量 |
| 跳过告知率 | 「跳过」项如实出现在「顺手未做项」的比例 | **必须 = 100%** | 漏告知即交付缺陷；累计 2 次判技能缺陷 |
| 降级验证次数 | 因预算 / 进度压力降低验证等级或跳过检查 | **必须 = 0** | >0 即事故，等同偷工减料 |
| 断言篡改次数 | 为通过测试而修改或跳过断言 | **必须 = 0** | >0 即事故，回退并告知 |

**成对原则**：任何压缩类指标（第 1 节）必须与至少一个防退化指标（第 2 节）配对存在。只上压缩不上护栏，本技能拒绝生效。

## 3. 团队场景指标

只数条目，不数 token（token 分散在多个会话，读不到）：

| 指标 | 算法 | 阈值 | 超阈处置 |
|---|---|---|---|
| 锚点覆盖率 | 已交付 R 编号 ÷ 待交付 R 编号总数（「不做」「已取代」不计入分母） | **必须 100%** | 未达即交付失败（同 H1） |
| 链式放大比 | 末环交付条目数 ÷ 锚点主体条目数（条目 = 清单中一行，一个可独立核销的功能 / 文件 / 文档节） | ≤2 正常；2–3 告警（交付说明加一句来源）；>3 失控 | 失控 → 回查哪一环在膨胀（多在架构层） |
| 未溯源占比 | `[未溯源]` 条目 ÷ 总条目 | ≤5% | 超出 → 任务书写得松，或成员在自行扩需求 |
| 单环条目占比 | 某环交付条目 ÷ 总条目 | >60% 提示一行 | **不拦截、不要求解释**——只是"有一环吃了大头"的信号 |

放大比是**警报器不是目标值**——压到 1 意味着设计与架构被砍光，那是另一种失败。

## 4. 采集时点

| 指标 | 时点 | 采法 |
|---|---|---|
| CR | 交付前（G3） | 逐条比对 G0 主体清单与交付清单，缺一即扣 |
| 文件数 / 依赖数 / 改动位置 / 重复次数 | 交付前 | 数交付清单与实际 diff |
| 返工率 / 二次追加需求率 | 下一轮用户消息时 | 识别"返工 / 遗漏"语义，计数 |
| 澄清 / 降级验证 / 断言篡改 | 全过程 | 事件计数，发生一次记一次 |
| 跳过告知率 | 交付前（G3） | 跳过项与「顺手未做项」逐条核销 |

## 5. 能力验收（判这个技能是否有效）

| # | 验收项 | 通过标准 |
|---|---|---|
| A1 | 判定可复现 | 换一个执行者，对同一行为按四步法得出同一结论；抽 10 条，一致率 **≥90%**，且每一条分歧都能归因到"可逆性判断"这一已知主观项（见 design-basis §5）。**归因由用户抽检确认，不由执行方自判**——自判等于自我豁免。归不到可逆性的分歧 = 规则有歧义，回修规则 |
| A2 | 强触发生效 | 有范围限定词 / 显式清单 / 单点需求时，X 级动作 100% 被处置（跳过告知 / 询问 / 停止），无静默执行 |
| A3 | 失效场景生效 | 用户要求全面审查或多方案时，零拦截 |
| A4 | 红线守住 | CR=100%、有效澄清拦截=0、降级验证=0、断言篡改=0、告知率=100% |
| A5 | **动作可核** | 交付清单逐项可溯源；文件数、依赖数、重复次数能逐条列出并被用户抽检 |
| A6 | 交互不劣化 | 单任务询问 ≤2 次；跳过项 ≤3 项（超出则合并为 1 次询问，裁决后计数清零） |

> A5 已从"R / R_x 能算出具体数值"改为"动作可逐条核"——原标准要求一件做不到的事，验收永远过不了，或者被迫编数。

## 6. 阈值怎么调

本技能的阈值只剩三个，且都是整数：**文件 +1、依赖上限 1、自检+复验 = 2**，加上累计升格的 **3 项** 与询问的 **2 次**。

调整方式：用户一句话即可（"以后允许 +2 个文件"），本次任务内生效。**不需要标定，因为它们不依赖估算**——这也是把 token 阈值全部删掉之后最大的收益。
