# 交付说明（附在主体交付物之后）

> 只写两段（团队三段），合计不超过"主体条目数 +2"行（「顺手未做项」按实际条数另计，≤5 行）。不写摘要、不写总结、不写变更报告——那些都是新增产物。
> 如果用户明确要一份完整的交付报告，那是主体要求，另说。

## 顺手未做项

| 动作 | 为什么没做 |
|---|---|
| （例）补一份 README.md | 用户没要求，不做也能交付 |
| （例）顺手统一另 12 处文案 | 改动面 1→13，超出最小改动面 2 倍 |

无则写一行：**无**。

> 100% 覆盖是硬要求。凡判为「跳过」的动作，必须出现在这里；漏一条即交付缺陷。

## 本次规模

`交付 ___ 个文件，新增 ___ 个｜询问 0/1/2 次`

> **只报事实，不报预估**——本技能不要求预估规模（见 SKILL §5）。新增数才是判"做没做多"的那个数。纯分析型交付写 `交付 0 个文件，新增 0 个`。

（团队场景再加一行）`返工：N 轮（>2 轮才写，附原因）｜未溯源项：0 / N 条（处置：删除 / 降级 / 补授权）`

---

## 填写示例

```
## 顺手未做项
| 补一份 README.md | 用户没要求，不做也能交付 |
| 顺手统一另 12 处文案 | 改动面 1→13，超出最小改动面 2 倍 |

## 本次规模
交付 5 个文件，新增 1 个｜询问 1 次（未获批，已跳过）

（团队场景）返工 3 轮（QA 两次打回，均为内容自相矛盾）｜未溯源项 2 条，均已降为建议
```

## 禁止在这些位置出现的内容

- 自查声明清单（"已检查 X、已确认 Y"超过 2 条）
- 规则复述（"按Agent-Behavior-Constraints要求，我判断…"）
- 判定过程展开（四步法怎么走的，用户不需要看）
- 额外生成的独立文件（越界审计报告、变更说明、CHANGELOG）
