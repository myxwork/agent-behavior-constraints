# 原话锚点表与委派任务书（预置团队用）

> 用在多角色预置团队里。**不改成员之间传递的内容**，只改主理人做记录和派活的方式。
> 表里的"原话"必须是用户真实说过的话，不许转述、不许概括——转述一次，往下每一环都会再宽一点。

## 一、原话锚点表

| 编号 | 需求条目 | 用户原话片段 | 状态 | 备注 |
|---|---|---|---|---|
| R1 |  |  | 待做 / 已交付 / 已剔除 / 已取代 |  |
| R2 |  |  |  |  |
| R3 |  |  |  |  |
| N1 | （用户明确不要的） |  | 不做 | 显式排除，任何环节不得擅自做 |

规则：
- 用户中途**追加** → 新增编号，不改旧编号含义
- 用户中途**修改**（非追加）→ 新增编号承接新含义，旧编号标「已取代」并注明承接编号，不计入覆盖率分母
- 每条主体要求都要有编号；有遗漏就等于给越界留了口子
- 交付前每条必须是"已交付"或"已剔除"，不许留"待做"；「已取代」「不做」不计入覆盖率

## 二、委派任务书（四段，每次派活照抄）

```
【本环负责】R__、R__（照抄原话，不改写）
【本环不做】R__（用户明确排掉）；以及任何新增功能、新增依赖、新增文档
【标记规则】超出上面两条的任何内容，写了必须标 [未溯源]；漏标视为违规
【交付格式】产物 + 一句话说明：哪些内容未溯源、各占多少
```

填写示例：

```
【本环负责】R1 加个导出 / R2 导出成表格 / R3 只要名字和电话两列
【本环不做】N1 PDF 导出；以及任何新增功能、新增依赖、新增文档
【标记规则】超出上面三条的任何内容，写了必须标 [未溯源]；漏标视为违规
【交付格式】需求说明 + 一句话说明：哪些内容未溯源、各占多少
```

## 三、收产物时的三问（主理人填，30 秒）

| 环 | 产物 | 挂不上锚点的内容 | 下一环必须做吗 | 剔除后主体完整吗 | 处置 |
|---|---|---|---|---|---|
| 1 产品 |  |  | 是 / 否 | 是 / 否 | 删除 / 降级 / 补授权 |
| 2 架构 |  |  |  |  |  |
| 3 工程 |  |  |  |  |  |
| 4 QA |  |  |  |  |  |

> 第 5 列若为"否"，**回到产生缺口的那一环补**，不要让下游顺便补齐——那就是新的越界。

## 四、交付前的核对

| 项 | 值 | 判定 |
|---|---|---|
| 锚点覆盖率 | 已交付 R 数 ÷ 待交付 R 总数（不含「不做」「已取代」） | 必须 100% |
| 链式放大比 | 交付清单条目数 ÷ R 条目数 | ≤2 正常；>3 失控 |
| 未溯源占比 U | `[未溯源]` 条目 ÷ 总条目 | ≤5% |
| 未溯源处置 | 删除 __ 条 / 降级 __ 条 / 补授权 __ 条 | 不得留存在交付物中 |

交付说明里补一行：`未溯源处置：删除 2 条、降级 1 条、补授权 0 条`
